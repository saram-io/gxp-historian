1. Purpose & Regulatory Scope

This Validation Master Plan (VMP) establishes the Computerized System Validation (CSV) and Computer Software Assurance (CSA) governance framework for the GxPHistorian GxP Industrial Historian deployed at BioCorp Fremont Biomanufacturing Operations. The platform replaces legacy proprietary OSIsoft PI System components with a 4-Pillar open-source architecture engineered for 21 CFR Part 11, EU EudraLex Volume 4 Annex 11, and ALCOA+ data integrity compliance.

4. Validation Lifecycle (IQ → OQ → PQ)

  • Installation Qualification (IQ): Automated verification (test_01_iq_infrastructure.py) of container health, non-default credentials, PostgreSQL extensions (ltree, btree_gist, pgcrypto), ClickHouse lossless compression codecs, and dictionary bridging.
  • Operational Qualification (OQ): Scripted positive and adversarial negative testing (test_02_oq_part11_compliance.py & test_03_oq_historian_core.py) verifying 21 CFR Part 11 WORM immutability, SHA-256 hash chain verification, electronic signature credential challenges, bad quality (quality < 192) rejection, linear vs. LOCF step interpolation, and LTTB peak preservation.
  • Performance Qualification (PQ): Continuous multi-protocol plant telemetry ingestion across 5 GxP tags (101, 102, 103, 301, 401), live Event Frame excursion capture, and Apache Parquet lakehouse exports.

5. Backup, Restore, Disaster Recovery & GitOps Change Control SOP

  • Database & Telemetry Backups: PostgreSQL pi_control_plane (including part11_audit_log) undergoes daily logical pg_dump and continuous WAL archiving to immutable object storage. ClickHouse pi_historian partitions (PARTITION BY toYYYYMM(ts)) are exported to Snappy-compressed Apache Parquet files and backed up via native ClickHouse BACKUP TABLE snapshots.
  • GitOps Change Control (SOP-IT-CHG-014): All infrastructure definitions (docker-compose.yml), database schemas (init-postgres/, init-clickhouse/), and API code (app/main.py, app/pi_parity_engine.py) are version-controlled in Git. Any change requires a pull request, automated execution of the 21-test IQ/OQ pytest suite (100% pass gate), and QA electronic approval prior to production deployment.

6. Hybrid Cloud & Commercial Edition Governance (EU GMP Annex 11 §4.3 & 21 CFR §11.30)

For regulated organizations deploying GxPHistorian Cloud (Managed Single-Tenant Cloud or BYOC Cloud Marketplace across Amazon Web Services, Microsoft Azure, and Google Cloud):

  • Purdue Level 2.5 Edge Autonomy (URS-005): Pillar 1 (edge-collector or pre-qualified GxPHistorian Edge Box DIN-rail IPC) always executes on-premises with a 100 GB local pSLC NVMe Write-Ahead Log (>14-day offline store-and-forward autonomy) and outbound-only TLS 1.3 / mTLS (:8443) transport.
  • Change-Controlled LTS Release Channels (2026.Q4-LTS): Cloud environments never undergo unannounced auto-updates. Every release is promoted to a customer staging environment first, where the 21-test pytest IQ/OQ suite executes automatically and mints a countersigned Validation Summary Report (VSR) prior to production promotion.
  • Quality Technical Agreement (QTA): Governed by the bidirectional Shared Responsibility Matrix in Document 05 (SOUP-GXPHISTORIAN-2026-005), granting annual QA postal/on-site supplier audit rights and guaranteeing 15-year 21 CFR 211.180 WORM retention (AWS S3 Object Lock COMPLIANCE, Azure Immutable Blob Storage, or GCP Bucket Lock).

1. 4-Pillar System Architecture

  • Pillar 1 — Multi-Protocol Edge Collector (edge-collector):
  • Built on telegraf:1.32-alpine with buffer_strategy = "disk" at /var/lib/telegraf/buffer (metric_buffer_limit = 1000000).
  • Exposes [[inputs.http_listener_v2]] on :8080/ingest for Windows localhost COM OPC DA forwarders (opcda_windows_forwarder.py) and async bacpypes3 BACnet/IP workers (bacnet_cov_worker.py).
  • Executes multi_protocol_simulator.py via [[inputs.execd]] implementing Stage 1 Exception/Deadband filtering (ExcDev and ExcMax) and Stage 2 Swinging Door Trending (CompDev and CompMax).
  • Pillar 2 — Immutable Telemetry Archive (clickhouse-archive):
  • clickhouse/clickhouse-server:24.8-alpine database pi_historian.
  • Table pi_historian.sensor_data (ENGINE = MergeTree() PARTITION BY toYYYYMM(ts) ORDER BY (tag_id, ts)):
  • tag_id UInt32 CODEC(Delta, ZSTD(1))
  • ts DateTime64(3, 'UTC') CODEC(DoubleDelta, ZSTD(1))
  • val Float64 CODEC(Gorilla, ZSTD(1))
  • str_val LowCardinality(String) DEFAULT '' CODEC(ZSTD(1))
  • quality UInt8 DEFAULT 192 CODEC(T64, ZSTD(1))
  • status_code UInt16 DEFAULT 0 CODEC(T64, ZSTD(1))
  • Real-time 1-minute rollup table pi_historian.sensor_rollup_1m (AggregatingMergeTree()) populated by mv_sensor_rollup_1m (WHERE quality >= 192).
  • In-memory dictionary pi_historian.pg_asset_tags (LAYOUT(FLAT()) LIFETIME(MIN 5 MAX 15)) and external table pi_historian.pg_event_frames.
  • Pillar 3 — PostgreSQL 16 Part 11 Control Plane, FastAPI, AVEVA PI Parity Engine & Pydantic AI / MCP (postgres-control + historian-api):
  • PostgreSQL 16 extensions: ltree, btree_gist, pgcrypto.
  • Tables: asset_templates, assets (GiST index on asset_path), tags, event_frames, event_frame_templates, event_frame_signatures, digital_state_sets, manual_logger_entries, notification_rules, notification_deliveries, users, and part11_audit_log.
  • Trigger fn_enforce_part11_audit() enforces current_setting('app.actor_id', true) and current_setting('app.change_reason', true) and computes row_hash = encode(digest(prev_hash || recorded_at::text || actor_id || operation || coalesce(new_payload::text, ''), 'sha256'), 'hex').
  • Trigger fn_prevent_audit_tampering() blocks UPDATE, DELETE, and TRUNCATE on part11_audit_log.
  • AVEVA PI System Parity Engine (pi_parity_engine.py) provides full PI DataLink (PICurrVal, PIArcVal, PICompDat, PIAdvCalcDat, PITimeFilter), PI Web API StreamSets, GxP calculations (MKT, F0, SQC), Golden Batch overlay, AF Template auto-instantiation, UOM conversion, PI Manual Logger, TrueFor Event Frame backfill, multi-stage e-signatures, and PI Notifications.
  • Pydantic AI Co-Pilot (gxp_ai_agent.py) & gxphistorian-mcp (mcp_server.py) provide read-only deterministic tools, progressive disclosure capabilities (part11-forensics, brownfield-onboarding), and human-in-the-loop ApprovalRequired (DeferredToolRequests) Part 11 change control.
  • Pillar 4 — Operator HMI & Excel DataLink (grafana-vision + excel-datalink-client):
  • Grafana OSS 11.2.0 pre-provisioned with clickhouse_core and postgres_control datasources and the asset-relative dashboard GxPHistorian Vision — GxP Bioreactor & Cleanroom HMI.
  • Excel DataLink UDF module (gxphistorian_datalink_udf.py) with 8 worksheet functions and native Power Query CSV endpoint (/api/v1/datalink/sampled?format=csv).
